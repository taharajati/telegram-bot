# 🤖 ربات مدیریت سفارش فروشگاهی تلگرام

ربات کامل و آماده‌ی اجرا برای فروشگاه‌های تلگرامی: مشتری‌ها محصولات رو می‌بینن، سفارش ثبت می‌کنن،
و ادمین از طریق پنل داخل خود ربات همه‌چیز رو مدیریت می‌کنه — بدون نیاز به هیچ پنل وب جداگانه‌ای.

## ✨ امکانات

**بخش مشتری**
- منوی دسته‌بندی و محصولات با صفحه‌بندی و عکس محصول
- سبد خرید کامل (افزایش/کاهش تعداد، حذف تکی، خالی‌کردن سبد)
- فرایند ثبت سفارش گام‌به‌گام (نام، شماره تماس، آدرس) با اعتبارسنجی شماره موبایل ایرانی
- کد پیگیری یکتا برای هر سفارش
- مشاهده‌ی تاریخچه‌ی سفارش‌های خود کاربر با نمایش تاریخ شمسی
- بخش پشتیبانی (پیام‌ها در صورت تنظیم بودن، به کانال ادمین فوروارد می‌شن)

**بخش ادمین** (`/admin`)
- مدیریت محصولات: افزودن (نام، توضیحات، قیمت، دسته، موجودی، عکس)، ویرایش تک‌تکِ فیلدها،
  فعال/غیرفعال کردن، حذف امن (بدون بهم‌ریختن تاریخچه‌ی سفارش‌های قبلی)
- مدیریت دسته‌بندی: افزودن و حذف
- مدیریت سفارش‌ها: لیست سفارش‌های در حال پیگیری، تاریخچه‌ی کامل، تغییر وضعیت
  (در انتظار → تأیید شده → ارسال شده → تحویل شده، یا لغو) با **اطلاع‌رسانی خودکار به مشتری**
- ارسال پیام همگانی (Broadcast) به همه‌ی کاربران، با رعایت محدودیت نرخ ارسال تلگرام
- آمار سریع فروشگاه (تعداد کاربر، محصول، سفارش و ...)
- دسترسی پنل فقط برای آیدی‌های تعریف‌شده در `ADMIN_IDS`

## 🧩 چند بهبود که خودم نسبت به طرح اولیه اضافه کردم

1. **حذف امن محصول/دسته‌بندی**: وقتی محصولی حذف می‌شه، به‌جای خطا گرفتن یا خراب‌شدن تاریخچه،
   سفارش‌های قبلی که اون محصول توشون بوده دست‌نخورده می‌مونن (چون قیمت و نام محصول جدا در
   `order_items` ذخیره شده) و فقط ارجاعِ محصولِ حذف‌شده null می‌شه.
2. **نمایش تاریخ به شمسی و اعداد فارسی** در قیمت‌ها و تاریخ سفارش‌ها (با `jdatetime`)، برای حس بومی‌تر.
   شماره تماس و کد پیگیری عمداً با رقم انگلیسی می‌مونن تا کپی/پیست راحت باشه.
3. **جابه‌جایی روان بین پیام متنی و عکس‌دار**: وقتی کاربر از یک محصولِ عکس‌دار به لیست متنی برمی‌گرده
   (یا برعکس)، تلگرام معمولاً روی edit خطا می‌ده؛ این حالت گرفته شده و پیام به‌درستی جایگزین می‌شه.
4. **Rate limiting داخلی** با `AIORateLimiter` فعاله تا در صورت ترافیک بالا، ربات توسط تلگرام محدود نشه.
5. **اطلاع‌رسانی خودکار به مشتری** هر بار که ادمین وضعیت سفارشش رو تغییر می‌ده.
6. یه اسکریپت تست داخلی (`tests/test_flow.py`) که کل جریان (ثبت‌نام → خرید → سفارش → تغییر وضعیت →
   حذف) رو بدون نیاز به توکن واقعی تلگرام شبیه‌سازی و اعتبارسنجی می‌کنه.

## 🚀 نصب و راه‌اندازی

### ۱. ساخت ربات در تلگرام
به [@BotFather](https://t.me/BotFather) پیام بده، دستور `/newbot` رو بزن و توکن رو ذخیره کن.
آیدی عددی خودت رو هم از [@userinfobot](https://t.me/userinfobot) بگیر (برای `ADMIN_IDS`).

### ۲. نصب پیش‌نیازها
```bash
cd telegram_order_bot
python3 -m venv venv
source venv/bin/activate        # ویندوز: venv\Scripts\activate
pip install -r requirements.txt
```

### ۳. تنظیمات
```bash
cp .env.example .env
```
فایل `.env` رو باز کن و مقادیر زیر رو پر کن:
- `BOT_TOKEN`: توکنی که از BotFather گرفتی
- `ADMIN_IDS`: آیدی عددی خودت (و هر ادمین دیگه‌ای)، با کاما جدا
- بقیه‌ی مقادیر (نام فروشگاه، واحد پول و ...) اختیاری‌ان و مقدار پیش‌فرض دارن

### ۴. اجرا
```bash
python3 main.py
```
اگه همه‌چیز درست باشه، پیام «ربات ... در حال اجراست» رو در ترمینال می‌بینی. دیتابیس و پوشه‌ها
به‌صورت خودکار در `data/` ساخته می‌شن؛ لازم نیست از قبل چیزی بسازی.

### ۵. تست بدون نیاز به توکن واقعی (اختیاری)
اگه می‌خوای قبل از گرفتن توکن مطمئن بشی همه‌چیز درست کار می‌کنه:
```bash
BOT_TOKEN=test ADMIN_IDS=1 python3 -m tests.test_flow
```
این اسکریپت با دیتای فرضی، کل جریان خرید و مدیریت سفارش رو تست می‌کنه و در انتها
«همه‌ی تست‌ها با موفقیت پاس شدن ✅» رو چاپ می‌کنه.

### ۶. اولین قدم بعد از اجرا
با اکانت ادمینت به ربات پیام بده و `/admin` رو بزن → «مدیریت دسته‌بندی‌ها» → یه دسته بساز →
«مدیریت محصولات» → اولین محصولت رو اضافه کن. حالا `/start` رو بزن و محصول رو ببین!

## 🖥 دیپلوی روی VPS

ساده‌ترین راه، اجرای دائمی با **systemd** هست:
1. پروژه رو روی سرور آپلود کن و مراحل بالا (venv + نصب + `.env`) رو انجام بده.
2. فایل نمونه‌ی `deploy/telegram-order-bot.service.example` رو کپی و مسیرها/یوزر رو با مقادیر
   واقعی سرورت جایگزین کن، بعد به `/etc/systemd/system/telegram-order-bot.service` منتقلش کن.
3. اجرا:
   ```bash
   sudo systemctl daemon-reload
   sudo systemctl enable --now telegram-order-bot
   sudo journalctl -u telegram-order-bot -f   # مشاهده‌ی لاگ زنده
   ```

راه ساده‌تر برای تست سریع (بدون systemd): از `tmux` یا `screen` استفاده کن تا با قطع شدن SSH،
ربات هم متوقف نشه.

## ⚠️ نکات مهم

- **پشتیبان‌گیری**: فایل `data/orders.db` تنها منبع داده‌ی شماست. مرتب ازش کپی بگیرید
  (مثلاً یه کران‌جاب ساده‌ی روزانه‌ی `cp data/orders.db backups/orders-$(date +%F).db`).
- **عکس محصولات** به‌صورت `file_id` تلگرام ذخیره می‌شن، نه فایل فیزیکی؛ یعنی برای آپلود عکس محصول،
  فقط کافیه توی مکالمه‌ی افزودن محصول، عکس رو مستقیم به ربات بفرستی.
- اگه `NOTIFICATION_CHANNEL_ID` رو خالی بذاری، سفارش‌های جدید و پیام‌های پشتیبانی فقط داخل
  پنل ادمین (`/admin` یا `/orders`) قابل‌مشاهده‌ان و نوتیفیکیشن جداگانه‌ای ارسال نمی‌شه.
- شماره موبایل فقط با فرمت ایرانی (`09xxxxxxxxx`) پذیرفته می‌شه؛ برای بازارهای دیگه باید الگوی
  `PHONE_PATTERN` در `handlers/order.py` رو عوض کنی.

## 💡 پیشنهاد برای توسعه‌ی بعدی

اینا رو عمداً برای نگه‌داشتن دامنه‌ی پروژه قابل‌مدیریت پیاده نکردم، ولی روی همین پایه راحت
قابل‌اضافه‌کردنن:

- فیلتر تاریخچه‌ی سفارش‌ها بر اساس بازه‌ی تاریخ یا وضعیت
- پشتیبان‌گیری خودکار روزانه از دیتابیس (مثلاً ارسال فایل db به کانال ادمین با کران‌جاب)
